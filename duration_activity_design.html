duration_activity — "how long was I doing that?"

Status: design only (2026-10-05). Nothing built. Counts below are measured off briefs_v4 tonight; the design is not. The headline number of this family — the constant-answer baseline — is unknown and cannot be estimated until the segmenter runs (§5).

Run the whole thing (once it exists): bash duplex/avd/run_duract_gates.sh → DURACT_CHAIN_OK.

Family string: duration_activity.

Sister document: docs/ACTION_NARRATION_DESIGN.md. The LLM activity segmenter (§4) is shared and is specified here, in full, once.

1. What the question is for

The wearer finishes doing something and wants to know how long it took.

"How long was I making that coffee?" "About four minutes."

Two things make it worth building. It is the only family whose answer is a number, so it can be scored exactly rather than judged. And it needs the model to hold a start time across an activity it was not asked about at the time — a different capability from answering a question about the present.

2. The activity must be meaningful

The owner's constraint, and it is the one that decides whether this family is real: the thing asked about must be an activity a person would name.

Good: making a coffee · playing with a ball · folding the laundry · washing up · playing an arcade game · setting the table.

Not activities: standing by the counter · adjusting posture · holding something · being in the kitchen · tiptoeing.

The second list is most of what the narration actually contains, which is why §4 exists.

3. When the question is asked

Two placements, per the owner.

placementgap after the activity endswhat it tests
immediatewithin ~10 sholding a start time across one activity
delayed2–3 minutesthe same, with other activities in between

The delayed one is the interesting half. By the time the question arrives the wearer has done one or two other things, so the model has to not report the duration of the most recent thing. That distractor is the point; without it the task is "how long was the last segment".

Two constraints follow:

  • The clip must run at least 2–3 minutes past the activity's end. Clips are

240 s, 390 s and 600 s, so delayed items will come mostly from the long ones. How many survive is unmeasured until segments exist.

  • The activity must end before the question starts. An activity still

running is a different question ("how long have I been…", §8) with a different answer and a different failure mode.

4. The LLM activity segmenter — the shared backbone

Both families depend on this and neither can be built without it.

Input: the ordered 5-second narration spans of one clip. Output: a list of segments, each {t0, t1, name, meaningful, evidence}.

4.1 Why it has to be an LLM

Cheap word-overlap merging was tried first and does not work. Merging neighbouring spans by shared content words — even after stripping a posture stop-list — produced themes like:

arms clasped lap leans forward backrest couch living floor pillow

That is body pose, not an activity, because body pose is most of what the narration is made of. One real activity did surface out of the whole corpus run (arcade button chair game joystick); the commonest theme words overall were living, forward, holding, area, leans, resting, arms, bends.

The run produced 588–1,184 "meaningful" segments at various thresholds, median ~67 s. Those numbers describe a rejected method and must not be quoted as a size estimate for this family.

4.2 Rules the segmenter must follow

  1. Only the narration. It names what the spans describe. It does not infer an activity the text does not support. Each segment carries the span indices that justify it.
  2. Boundaries snap to span edges. The spans are the only timing evidence there is; a boundary invented between them is a guess with a decimal point on it.
  3. It marks meaningful itself, against §2, and the unmeaningful segments are kept in the output rather than dropped — a segment rejected silently is a segment nobody can audit.
  4. Segments do not overlap and do not have gaps. Dead time between activities is its own segment, marked unmeaningful.

4.3 Boundary error is duration error

This is the thing that will decide whether the family is any good.

If the segmenter says the coffee started at 120 s and it really started at 105 s, the duration is wrong by 15 s — and at a 4-minute activity that is inside a ±20% tolerance, while at a 45-second activity it is not. Short activities are far more sensitive to boundary error than long ones.

So two things are required:

  • A second independent pass over each boundary: a different prompt, or a

vision check on the frames either side. Disagreement widens the uncertainty band (§6), it does not get resolved by preferring one.

  • A minimum duration floor, set from the measured boundary spread rather

than chosen. If boundaries land within ±8 s, a 45-second activity cannot be scored at ±20% and the floor has to rise.

4.4 Model

Gemma-3 27B/31B via transformers (not vLLM), which fits one H200, or Qwen3-Omni-30B. Narration text only — no video — so this is cheap per clip and runs over all 477 in one sweep.

5. The baseline problem, and why posture is not the answer

A duration family is easy to build and easy to fake. If most answers are near one value, a model that ignores the video and says that value every time scores well.

This was measured on the cheap version of the family — posture states (sitting / standing / walking), merged from the narration, which is the obvious first idea:

setitemsmedianbest single constant answer
all states, runs ≥20 s1,36532 s62.6%
all states, runs ≥45 s46977 s41.4%
all states, balanced across duration octaves68—25.0%
sitting only, ≥45 s110148 s25%

A model answering "about 30 seconds" to everything is right 63% of the time on the obvious version of this family. The cause is standing and walking: thousands of runs, median 10 s each, piled on one value.

Posture duration is therefore not the family. It survives only as a small side arm (§8), built on sitting and lying, where the spread is wide enough that a constant answer gets 25%.

The activity version is expected to be better — named activities should be longer and more varied than postures — but that is a hypothesis, not a measurement. The constant-answer baseline must be recomputed on the LLM segments before any item ships, and if it is above ~30% the family is rebalanced or cut. It is reported next to every score forever after.

6. What the answer looks like

Stored as a number with a band; spoken as a person would say it.

`` answer_s : 247.0 the point estimate answer_band : [232.0, 262.0] the honest uncertainty, from §4.3 answer_text : "about four minutes" ``

  • Score numerically, against the band — not by string match. This is

what makes the family worth having.

  • Tolerance is relative: ±20%, with a floor of 10 s. Nobody says "247

seconds", and a fixed ±15 s is far too generous at four minutes and impossible at thirty.

  • answer_text is rendered from the number, never written by hand, so

the spoken form cannot drift from the thing being scored.

  • The band comes from the two-pass boundary check. **An item whose band is

wider than its own tolerance is not scorable and does not ship.** That is a real filter and it will remove items.

Accepted model answers include "about four minutes", "four minutes or so", "roughly 250 seconds", "a bit over four minutes". The scorer parses a number and a unit out of the answer; an answer with no parseable number is wrong, not unscored.

7. What the question looks like

"How long was I making that coffee?" "How much time did I spend playing with the ball?" "That laundry — how long did that take me?"

Rules:

  • Name the activity. Like the memory families and unlike the deictic

ones, the question identifies its target. A bare "how long did that take?" has no defensible referent two minutes later.

  • Past tense for finished activities. Present perfect (*"how long have

I been…"*) belongs to the ongoing arm (§8) and must not be mixed in; the two have different answers at the same moment.

  • No duration hint. "Was that about five minutes?" gives it away.
  • Wording varies, intent preserved. A guard fails the build if any single

phrasing exceeds a fifth of the family.

7.1 The decline arm

Some activities begin before the clip does. Their true duration is unknowable, and the correct answer is to say so:

"I only started watching partway through that, so I can't say how long in total — at least three minutes."

This is worth building deliberately rather than filtering out. Decline teaching has already paid off once in this project, and a duration model that confidently invents a number for an activity it never saw the start of is exactly the failure mode to train against. Target a small share, around 10%.

8. The posture side arm

Kept small, and only where the baseline holds up: sitting and lying, runs of 45 s or more, onset inside the clip. 110 sitting items, median 148 s, p90 490 s, constant answer 25%.

These use the present-perfect form, "how long have I been sitting here?", and are the only items in the family asked during the state rather than after it. They are flagged and scored separately. Standing, walking and crouching are excluded outright for the reason in §5.

9. Visual verification

This family ships a number that no frame has confirmed. The segmenter reads narration text only (§4.4); the duration is one text-proposed boundary subtracted from another. Everything that makes the family attractive — an exactly scorable answer — rests on two timestamps that came out of prose.

9.1 Two text passes do not make an independent check

§4.3 offered the second boundary pass as a different prompt, or a vision check. That choice is withdrawn: the vision check is mandatory on both boundaries of every shipped item.

The reason is that the error here is systematic, not random. The narrator names an activity once it is underway, so a text pass is late at the start boundary and late at the end boundary, and a second text pass over the same prose is late in the same direction. Two passes agree, the band stays narrow, and the number is confidently wrong. In the sister family that same lag overturned 2 of 18 anchors — and there it cost an anchor, here it costs seconds straight off the answer.

So the band in §6 comes from text-versus-vision disagreement. A text-versus-text band is not an uncertainty estimate; it is an agreement between two instruments with the same fault.

9.2 How the boundaries are checked

Coarse 2 fps over the segment to bracket each boundary, then dense 15 fps in the bracket to place it. The verifier answers a closed question — is the activity underway in this frame — because a free-text verdict cannot be gated. It must pass a control in the middle of the segment, where the activity is known to be running, before any "not yet" is believed.

9.3 The arms that are visual claims outright

  • The decline arm (§7.1) asserts the activity began before the clip.

That is a statement about the first frames, and it is checked there. An item whose opening frames show the activity starting is not a decline item; it is a mislabelled one, and it teaches the model to refuse answerable questions.

  • The posture arm (§8) turns on a sitting or lying onset. Posture is

the single thing the narration says most often and the thing it is loosest about. The onset frame is confirmed.

9.4 Disagreement widens, it does not resolve

Where vision and text disagree on a boundary, the band widens to cover both. If the widened band is wider than the item's own tolerance, the item does not ship (§6) — and that is the gate doing its job, not a yield problem to be tuned away. The disagreement is quarantined with the reading written down.

10. Data defect: 121 broken spans

121 action spans have an end at or before their start, including negative times: [2.2, -0.3], [403.5, 400.7]. This family computes durations off that grid, so a backwards span is a negative duration feeding straight into an answer key.

Quarantined with the reason written down, never deleted, before the segmenter runs.

Step 5 is a gate, not a report. If the baseline on real segments comes back high, the chain stops there and the family is rebalanced before anything is authored on top of it.

13. Open

  1. The baseline on real activity segments. The single biggest unknown. Until step 5 runs, the size and the viability of this family are both unknown.
  2. Boundary spread, which sets the minimum activity duration (§4.3).
  3. How many delayed items the clip lengths allow (§3).
  4. Whether the segmenter's own meaningful judgement matches a person's. A hand audit of ~40 segments settles it, and it should run before anything is built on top.
