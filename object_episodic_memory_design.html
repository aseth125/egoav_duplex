Object-episodic memory questions — end-to-end design

Status: design + three stages built and tested (2026-10-05). Nothing has shipped yet. 227 object_memory turns exist in specs_v51 and none of them has ever been checked against the video, which is the whole reason this document exists.

Run the whole thing: bash duplex/avd/run_objvis_gates.sh → OBJVIS_CHAIN_OK (stops at the first non-OK token, producers before consumers).

Sister document: docs/EPISODIC_MEMORY_DESIGN.md covers the action family — "what was I doing before X". This one covers the object family — "where did I put X". They share the no-future rule and the fixture-pair convention and nothing else.

1. What the question is for

The wearer put something down, did something else, and now wants it back.

"Where did I put the cup?" → "On the table in the living room — you put it there about two minutes ago."

This is the most ordinary thing anybody asks an always-on assistant, and it is a real memory test only if three things are true at the moment of asking:

  1. The object was genuinely in the wearer's hands at some point. If the narration invented the placement, the answer key is fiction.
  2. The object is not on screen when the question is asked. If the cup is sitting in frame, the model does not remember anything — it looks. This is the condition all 227 current rows fail to establish, and on the eight published episodes 3 of 5 ask about something in plain sight.
  3. Nothing after the ask is used to justify the question or the answer. A question proved correct with frames the wearer has not lived through yet is proved against nothing.

Condition 2 is the owner's design and it has two halves, both required:

check if the ball is present in that time period; if yes then move forward and find a different action / scene and check the ball is not present — and ensure that during the time span when the question is asked, each individual frame does not have the object present.

The first half is the control. Skip it and a detector that finds nothing scores a perfect absence on every window and certifies a corpus whose answers are centre-frame. The control is not a quality nicety; it is the thing that makes the absence mean anything.

2. Where the questions come from

Two sources, and they are not alternatives — the second is much larger.

2.1 Handled objects (the existing 227)

Narration text. objvis_tasks.handled_objects() scans briefs_v4 for a HANDLE verb plus a noun — puts, places, sets down, picks up, grabs, holds, carries, leaves, returns. Objects are keyed on the head noun, so "the ball", "the ball with" and "the ball using" are one candidate and not three; three would triple detector cost and report the same fact three times. An object mentioned once is a parse accident and is dropped.

A separate regex, objvis_tasks.asked_object(), reads the object back out of each existing question. It needs two shapes, not one:

formcount
"where did I put the X?"175
"where's the X?"52

A parser built from the first shape alone drops 23% of the corpus, and the hole shows up as "the narration never mentions this object" — a defect in the question that is really a defect in the regex.

Yield: 195 of 227 turns match a handling span. The other 32 name something the narration never says the wearer touched; they are written out with status: "no_handling_span" rather than silently dropped.

2.2 Static objects the wearer never touches (new, much larger)

The owner's third idea, and the ground truth is free:

we can talk about some static object that are present, the person never touches them, but due to him moving they are not visible, and then he wants to know where is that static object

The Nymeria annotation files already track scene furniture with a per-frame visibility score and bounding box. For these objects no detector is needed at all — the data says exactly when the thing is on screen.

Measured across all 214 annotated sequences:

static tracked objects24,002
seen at some point, then out of view ≥45 s20,288
clips covered214 of 214
median out-of-view gap269 s

Askable categories: lamp 2,592 · wall art 1,343 · door 1,335 · window 1,112 · chair 1,115 · table 993 · plant 881 · couch 420 · screen 282 · storage 2,732. Rejected categories: wall, floor, ceiling, stairs, and the catch-all Anything — "where is the floor" is not a question.

This family is cleaner than the handled one (free ground truth, no detector error) and roughly a hundred times larger. It is not interchangeable with it: a handled object tests did you track my action, a static object tests did you build a map of the room.

3. What the question should look like

Short, spoken, and it must name the object. This family deliberately inverts the deictic rule used everywhere else: no "that", no "it", no "the one I had". Naming the object is what makes a long delay safe — there is no referent to mis-resolve, so old evidence is the point rather than the defect.

Good:

"Where did I put the cup?" "Hold on — where's the remote?" "Sorry, where did I leave the blue folder?"

Static-object form:

"Which room is the standing lamp in?" "Where was that picture on the wall?"

Not acceptable:

  • "Where did I put it?" — bare pointer, no referent.
  • "Where's the cup I just set down?" — "just" makes it perception.
  • "Where did I put the cup before I started the laundry?" — an anchor the

wearer may not have reached yet. If an anchor is used at all it goes through the action family's ANCHOR_TIMING gate.

  • "Where did I leave my colleague?" — people, body parts, rooms and

fixtures are in NOT_OBJECT for a reason; the narration says "holding the peer" constantly.

4. What the answer should look like

Three parts, in this order. Parts 1 and 2 are required.

"In the box — you put it there a little over a minute ago." "On the kitchen counter, in the room you were in before — about two minutes ago."

  1. The preposition and the surface, carried verbatim. in the box, not on the box. Normalising every placement to "on the" was the single largest error class in the hand audit (11 of 40 turns). A model that correctly answers "it is inside it, not on it" would be marked wrong by its own key. Shipped specs_v51 now reads On 171 / In 54 / Under 1, so the fix is in the data.
  2. How long ago, in rough speech ("about a minute ago"), never a timestamp.
  3. The room, when the narration names one — optional but preferred. The owner's phrasing, "on the table in the room you were in before", is better than ours because it is how a person actually answers.

4.1 Where the destination comes from — two routes

Route A, narration. objmem.PLACE requires all four of verb + object + preposition + destination. A bare verb alternation reported 12,508 placements because it read "turns left" as "left it somewhere"; the full frame drops that to 2,575 real ones. This is the route all 227 current answers use.

Route B, vision — for when the narration does not say. The owner's case:

if you do not have this information then we first need to confirm the presence of the ball and then ask the VLM to find where is the ball, and then we can understand that ok it is on the table, and then form the answer

Order matters and is not negotiable: confirm presence first, then ask where. A VLM asked "where is the ball" on a frame with no ball will answer anyway, and it will sound reasonable.

Route B is also a free cross-check on Route A. When both run and disagree — narration says table, vision says counter — the row is quarantined with the disagreement written down, not resolved by preferring one.

Static objects always use Route B, on a frame where the track says the object is visible and which falls before the ask.

4.2 The answer must still be true at the ask

A placement is not permanent. If the wearer picked the thing up again before the question, the key is wrong — and wrong in a systematic direction, which is worse than wrong at random. objmem_audit.py calls this a missed pickup; it is checked by listing every later sentence naming the object head, not by matching a verb whitelist. A whitelist misses "she slides the cup across to the sink", which moves the object and contains no listed verb.

Only mentions at or before the ask may be read. See §6.

5. Visual verification — the gate, step by step

This is the part that does not exist yet for any shipped row.

5.1 Two passes, not one dense sweep

"Every individual frame" at 15 fps over a 300 s clip is 4,500 frames, times 116 clips, times a detector call. That is real money spent searching ground the narration already ruled out. So:

passrateoverjob
coarse2 fpsthe top-ranked candidate windowschoose where to look
dense15 fpsthe one window that shipsthe gate itself

The dense pass is the gate. The coarse pass only aims it. A coarse miss costs a candidate window and can never cause a false pass, because nothing ships on coarse evidence.

Cost after scoping to the real turns and applying the no-future rule: 20,024 coarse + present frames. Minutes on a handful of GPUs.

The first version of the builder emitted 1.3 million frames by scanning from the first candidate window to the end of every clip for every object. Ranking first and reading four windows is the same answer for 3% of the calls.

5.2 Both arms, every candidate

armframesmust be
present (control)1 fps inside the handling spansobject found
absentevery frame of the shipped windowobject found nowhere

A candidate whose present arm is weak is dropped, not shipped with a warning. No control, no question.

5.3 The prompt is not one string — measured

SAM3's answer depends sharply on the exact words, and no single form wins:

promptframes found
drinking cup0 / 14
cup13 / 14
remote control14 / 14
control0 / 14
hand (sanity)14 / 14

So every object is probed with both the head noun and the full phrase. The control arm decides which form works, and that same form is then used for the absence check — otherwise the two arms are different detectors and the comparison is meaningless.

The hand row is there as a frame-sanity check: if even "hand" is not found in a first-person clip of someone handling something, the frame is bad, not the prompt.

5.4 Two detectors, not one

  • SAM3 does the dense pass. Text-prompted, fast enough for every frame.
  • Qwen3-Omni 30B re-checks a sample of SAM3's verdicts. It is far too

slow for per-frame work (the old object_visibility_gate.py called it one frame at a time) but it is the only thing that can catch SAM3 being confidently wrong in a consistent direction.

If the two disagree badly on the sample, the sweep is void. A disagreement is not a negative.

6. The no-future rule

make sure this episodic memory question, so future thing should not be referred

Three separate places, all of which were wrong in the first draft or are wrong in the shipped data:

  1. The probe window must end at the ask. The first builder centred the window on the ask time, so half of every window was video that had not happened yet. Proving "the cup is not on screen" with future frames proves nothing.
  2. The answer's evidence must precede the ask. Placement time < ask time, and the missed-pickup scan reads only mentions ≤ ask.
  3. The answer text may not mention anything later than the ask.

This rule is expensive and the cost is visible:

centred window (wrong)ends at ask (correct)
turns with no alternative window35122 of 195
frames to check30,57620,024

Two-thirds of existing questions have nowhere to move to once the future is off limits. They pass or fail where they sit. The earlier 35 was low only because it was counting windows made of video that had not happened.

Guarded by test_objvis_tasks.py, which carries a fixture pair for each rule — one case that must trip it, one that must not. A test showing only rejection passes just as happily when the gate rejects everything, and a gate that rejects everything looks exactly like a gate that works.

7. Why gaze does not solve this

Every clip has eye gaze — ~2,300 samples, about 2 per second, with a screen point and a focus depth. It was checked and it is not the answer:

  • Gaze says where the wearer is looking, not what is in frame. The

camera sees far more than the eyes rest on. The cup can be in plain sight while they look at the stove; gaze would call it hidden.

  • The gaze point is in screen coordinates, and the screen moves with the

head. Converting it to a fixed place in the room needs head pose, which is not in these files.

What gaze is good for, and should be used for:

  1. Checking a placement is real. People look at what they put down, at arm's length. If depth_m is 4 m at the moment the text says "puts the cup on the table", the text is probably describing something else. Free.
  2. Narrowing the dense pass, so the detector reads fewer frames.

The per-frame vis field on tracked objects is the right instrument — but it matches only 9 of 227 handled objects, because the track vocabulary is furniture. That same limitation is exactly why it is perfect for the static family (§2.2).

4objvis_decide.pyOVD_OKcontrol gate, pick the clean window, site the question

6objvis_answer.pyOVA_OKRoute B destinations where narration is silent
7objmem_audit.pyOBJ_AUDIT_OK40-row hand audit, re-run against the current build
8objstatic_tasks.pyOST_OKstatic family from track visibility

Steps 4–8 are not built yet. 1–3 are built and tested.

Order is load-bearing: the control gate (4) must see the prompt-form results (3) before it can choose which word the absence check used, and the audit (7) must run against the build that ships, not an ancestor of it.

9. What "done" requires — the checklist

Before any object-episodic row ships:

  • [ ] OBJ-01 Object parsed from the question by both regex shapes.
  • [ ] OBJ-02 A handling span exists in the narration (or it is a static track).
  • [ ] OBJ-03 Control passes: the object is found in the handling frames, under a named prompt form.
  • [ ] OBJ-04 The same prompt form is used for the absence check.
  • [ ] OBJ-05 Every frame of the shipped window is clean — not a sample.
  • [ ] OBJ-06 The window ends at or before the ask.
  • [ ] OBJ-07 The window is a different activity from the handling.
  • [ ] OBJ-08 Gap from last handling ≥ 45 s.
  • [ ] OBJ-09 The answer carries the exact preposition.
  • [ ] OBJ-10 No pickup between placement and ask (all later mentions read, not a verb whitelist).
  • [ ] OBJ-11 Nothing in question or answer refers past the ask.
  • [ ] OBJ-12 A 30B sample agrees with SAM3.
  • [ ] OBJ-13 The 40-row hand audit has been re-run on this build and clears ≥90% correct with no error class above 5%.

The last line is currently 50% correct (20 of 40) — and that number is against specs_v28, before the preposition fix and before the still arm was dropped. It has never been re-run. Unknown, not fine.
